# Tikkit

Event discovery and ticketing for the Maldives. Times are shown in Maldives time (UTC+5), prices in MVR, and the weekend is Friday and Saturday.

Expo SDK 57 · React Native 0.86 · New Architecture + Hermes (both are mandatory/default in this SDK, nothing to toggle) · iOS 16.4+, Android, and web. Portrait on phones.

Preview on a phone with **Expo Go** (`npm run go`, scan the QR). Release builds use an Expo development build so native modules behave as in production. Native folders (`ios/`) are generated by `expo prebuild` and git-ignored; configure native behavior in `app.json` and config plugins.

## One-time setup (macOS)

```sh
# 1. Install Xcode from the App Store, then point the toolchain at it
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

# 2. Accept the license and install first-launch components (includes command line tools)
sudo xcodebuild -license accept
xcodebuild -runFirstLaunch

# 3. Install an iOS Simulator runtime (~8 GB)
xcodebuild -downloadPlatform iOS

# 4. CocoaPods (use Homebrew; macOS system Ruby is too old for `gem install`) and Watchman
brew install cocoapods watchman

# 5. JS dependencies
npm install
```

Check it worked: `xcrun simctl list runtimes` should list an iOS runtime.

## Backend (Supabase)

Postgres, auth and photo storage run locally in Docker (OrbStack works and is lighter) via the Supabase CLI. The same migrations deploy unchanged to a hosted Supabase project.

```sh
npm run db:start          # first run downloads images; prints the URL and publishable key
cp .env.example .env.local  # paste the URL and publishable key
npm start
```

| Command | What it does |
| --- | --- |
| `npm run db:start` / `db:stop` | Start or stop the local stack (the Studio dashboard is left off to save about 340 MB; run `npx supabase start` without `-x` when you want it) |
| `npm run db:reset` | Rebuild the database from `supabase/migrations` and `supabase/seed.sql` |
| `npm run db:test` | Security tests in `supabase/tests` (who can read and write what) |
| `npm run db:types` | Regenerate `src/lib/database.types.ts` after a schema change |

- **Test accounts (local only, all `password123`)**: `admin@eventspace.mv` is an admin and verified organiser and owns most sample events and spaces (development builds show a "Sign in as test admin" button). `aminath@eventspace.mv` is a verified organiser with her own events and a promoter link. `newbie@eventspace.mv` has a verification, a draft-to-review event and a space check waiting, so the admin queue has work in it. Any other email (code in Mailpit) is a fresh account.
- **Sign-in**: 6-digit email code, plus Google. Local emails land in Mailpit at http://127.0.0.1:54324. Google needs credentials in `supabase/.env` (see `supabase/.env.example`) and `enabled = true` in `supabase/config.toml`.
- **Phones**: set `EXPO_PUBLIC_SUPABASE_URL` to your Mac's LAN or Tailscale IP, not 127.0.0.1.
- **Security model**: row level security on every table; the app can only read. Every write (buying, check-in, transfers, refunds, creating events, door staff, account deletion) goes through a database function that checks who is calling and validates input. Inventory and ticket codes are only ever set by the server. Sessions are stored in the iOS Keychain / Android Keystore.
- **Venues and rentals**: anyone can add the venues they run (Organiser > Your spaces) and pick one when creating an event. A space is listed under Find a space only once it's verified (proof of the right to rent plus an on-site location check, which also pins it on the map). Organisers request a time; when the owner approves, the renter has 48 hours to pay in the app. Approved bookings can never overlap (a database exclusion constraint), and an event can only use a paid booking. The owner is credited the rental less a 10% commission the day after.
- **Trust** (`supabase/migrations/20261016000000_trust.sql`): anyone can draft events. Unverified people's events stay drafts; verified people's events wait for admin review; organisers with 3 clean past events and no upheld reports are trusted and publish straight away (shown to admins for spot checks). Only approved events are public or buyable. Reports from 3 people saying "scam" or "fake" freeze an event's payouts. Admins work from Account > Admin.
- **Payments** (`supabase/migrations/20261016010000_marketplace.sql`): buyers always pay Tikkit, never the organiser. Checkout holds tickets for 20 minutes (bank transfers up to 24 hours) and releases them when the hold expires. Card payments go through Bank of Maldives Connect (`supabase/functions/payments`), which settles only after fetching the transaction from the bank itself. Bank transfers are confirmed by an admin matching the ES- reference against the bank statement; payment slips are never accepted. Sellers are credited in a ledger that becomes withdrawable a few days after the event, which is what funds refunds when an event is cancelled or taken down (the Tikkit Guarantee). Fees, hold periods and prices live in `private.settings`.
- **Locally**, `seed.sql` sets `card_provider = 'mock'`: a test card page in the app follows the BML Connect flow without moving money (4242 4242 4242 4242 succeeds, 4000 0000 0000 0002 declines), and a sample bank account is set for transfers.

### Going live with card payments (BML Connect)

1. Get API keys from the BML merchant portal (sandbox first; the sandbox talks to `api.uat.merchants.bankofmaldives.com.mv`).
2. `npx supabase secrets set BML_API_KEY=... BML_MODE=sandbox RETURN_URL_PREFIXES=eventspace://,https://eventspace.mv/`
3. `npx supabase functions deploy payments`
4. In BML's portal, point the webhook at `https://<project>.supabase.co/functions/v1/payments?webhook=1`.
5. Switch the gateway on: `update private.settings set card_provider = 'bml';` and set your real `bank_name`, `bank_account_name`, `bank_account_number` for transfers.
6. Confirm BML's transaction state names against their current docs (the function treats `CONFIRMED` as paid), run a sandbox purchase end to end, then set `BML_MODE=production`.

### Share links

`supabase/functions/share` gives event links a proper preview (title, date, price and a generated 1200×630 poster) when pasted into Instagram, WhatsApp, Viber or iMessage, then sends people on to the web app. Deploy it with `npx supabase functions deploy share`, set `WEB_URL` (and `SHARE_PUBLIC_URL` if you put it behind your own domain), route `https://eventspace.mv/e/*` to it, and set `EXPO_PUBLIC_SHARE_URL=https://eventspace.mv`. Locally, `npx supabase functions serve` runs it at `http://127.0.0.1:54321/functions/v1/share/e/<event-id>`.

### Sharing straight to Instagram Stories

The story card on an event (and "Share that you're going" on a ticket) opens Instagram's Story composer directly, with no share sheet, using Instagram's own Stories entry point. It's a small local native module in `modules/instagram-stories` (iOS pasteboard + `instagram-stories://`, Android `ADD_TO_STORY` intent), so:

- It needs a **development or store build** (`npm run ios`, or `eas build`). Expo Go and the web fall back to the share sheet.
- Instagram requires a **Facebook App ID**: create an app at developers.facebook.com and set `EXPO_PUBLIC_FACEBOOK_APP_ID` in `.env.local` (and in EAS environment variables). Without it, sharing falls back to the share sheet.
- The event link is copied as the composer opens, so people add a Link sticker and paste it.

### Series, seats and memberships

`supabase/migrations/20261017000000_series_seats_members.sql` adds repeating events (up to 12 dates, reviewed as one), seat maps (seats are held with the payment and released when it expires; tickets carry their seat), organiser memberships with members-only presales and a member discount, reviews of organisers from people who were checked in, copycat-title and high-price flags for admin review, payout flags when the bank account name doesn't match the verified name, and scam alerts to ticket holders, savers and followers when an event is taken down.

Make yourself an admin on a hosted project with `insert into private.admins (user_id) values ('<your auth user id>');` in the SQL editor.

### Moving to hosted Supabase

```sh
npx supabase login
npx supabase link --project-ref <ref>
npx supabase db push        # applies supabase/migrations (seed data is not pushed)
```

Then put the project URL and publishable key in `.env.local` (or EAS environment variables). In the dashboard: Auth > URL Configuration, add `eventspace://**` to redirect URLs; Auth > Providers, enable Google and keep "Confirm email" on (the app trusts a signed-in email for ticket transfers and door-staff invites); Auth > SMTP, add a real email sender.

## Running

| Command | What it does |
| --- | --- |
| `npm run ios` | Prebuild, compile, and launch on the default simulator |
| `npm run ios:se` | iPhone SE (3rd generation), the smallest supported screen |
| `npm run ios:max` | iPhone 17 Pro Max |
| `npm run ios:dark` | Boots iPhone 17, switches it to dark appearance, launches |
| `npm run ios:light` | Switches the booted simulator back to light |
| `npm start` | Metro only (after a dev build is installed) |
| `npm run prebuild` | Regenerate `ios/` from scratch |
| `npm run typecheck` / `lint` / `test` / `doctor` | Checks |

The first `npm run ios` takes several minutes (pods and native compile). After that, JS changes hot-reload; only native changes (new native module, `app.json` plugin edits) need another `npm run ios`.

## Simulator behavior

| Capability | Simulator | Handling |
| --- | --- | --- |
| Camera | none | `/scan` redirects to manual code entry (`src/lib/device.ts`) |
| Haptics | none | wrappers in `src/lib/haptics.ts` swallow failures |
| Push | works via `xcrun simctl push` and real APNs on Apple silicon | stubbed in `src/lib/services/push.ts` until configured |
| Apple Pay | sheet works with sandbox test cards | stubbed in `src/lib/services/payments.ts` until a provider is chosen |

xcrun simctl status_bar booted override --time 9:41 --batteryState charged --batteryLevel 100
